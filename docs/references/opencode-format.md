# OpenCode — Local Data Format

## Paths

- **Database**: `<data-dir>/opencode/opencode.db`
  - `<data-dir>` is `$XDG_DATA_HOME` when set, else `~/.local/share`
    (on every platform, macOS included).
  - SQLite, WAL mode. omnisess opens it read-only (`?mode=ro`) and never
    writes to it.
  - Side files `opencode.db-wal` / `opencode.db-shm` may exist while OpenCode
    is running; a read-only connection sees committed WAL content.

## Schemas

Two schema generations exist. Current releases write **v2**; the legacy tables
remain in upgraded databases but are not consulted when `session_v2` exists.

### v2 (current)

```
session_v2     one row per session
session_message  conversation messages, one row per turn, ordered by seq
```

`session_v2` columns consumed by omnisess:

| Column | Use |
|---|---|
| `id` | session ID (`ses_…`) |
| `title` | session title (LLM-generated by OpenCode) |
| `directory` | project working directory |
| `model` | JSON: `{"id":"…","providerID":"…"}` |
| `time_created` / `time_updated` | unix milliseconds |

`session_message` columns consumed by omnisess: `session_id`, `type`, `seq`,
`data`. Message parts are **inlined** in `data` (the `session_part` table is
not used by current releases).

`data` payloads:

```json
// type=user
{"time":{"created":1700000001000},"text":"…","files":[],"agents":[]}

// type=assistant
{"time":{"created":1700000002000},"agent":"build",
 "model":{"id":"…","providerID":"…"},
 "content":[
   {"type":"reasoning","text":"…"},
   {"type":"text","text":"…"},
   {"type":"tool","id":"call_1","name":"read",
    "state":{"status":"completed","input":{…},"output":"…"}},
   {"type":"tool","id":"call_2","name":"grep",
    "state":{"status":"completed","input":{…},
             "content":[{"type":"text","text":"…"}]}},
   {"type":"step-start"}
 ]}
```

- `type` values other than `user` / `assistant` (`system`, `shell`,
  `synthetic`, `compaction`, `idle`) are not rendered.
- Tool results appear either as a `state.output` string or as a
  `state.content` array of `{type:"text"}` blocks. Both are read.
- `state.status == "error"` marks a failed tool call.

### Legacy (pre-v2)

```
session   one row per session        (id, title, directory, model, times)
message   one row per turn           (id, session_id, time_created, data)
part      one row per content block  (id, message_id, time_created, data)
```

`message.data` is `{"role":"user"|"assistant","time":{"created":…}}`; the body
lives in `part` rows:

```json
{"type":"text","text":"…"}
{"type":"tool","tool":"read","callID":"…","state":{"status":"completed","input":{…},"output":"…"}}
```

Other part types (`reasoning`, `step-start`, `step-finish`, `patch`, …) are
ignored. Legacy support is read-only and only used when `session_v2` is absent.

## Notes

- Session IDs are displayed as `opencode:<id>`. `omnisess show` accepts a
  unique ID prefix.
- Active detection is the shared fallback: the `opencode` process is running
  **and** the session row was updated within the last 10 minutes.
- The older file-based OpenCode layout (JSON files under `storage/`) is not
  supported.
